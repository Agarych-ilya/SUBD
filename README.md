# ЛР №1 по СУБД — вариант 9

Тема: **«Управление научными исследованиями по тематическому плану»**.

## Что уже сделано

- общий GUI на PyQt6;
- главное меню: **Данные / Анализ / Помощь / Выход**;
- отображение таблиц НИР, финансирования, VUZ и рубрик ГРНТИ;
- понятные русские заголовки вместо `f1`, `f10`, `f18` и т. п.;
- VUZ и ГРНТИ работают только на просмотр;
- фильтрация/поиск по выбранному полю;
- автоматическое заполнение `Z2` по `CODVUZ` при первичной загрузке;
- нормализация `RNW` без пробелов;
- нормализация двух кодов ГРНТИ: запятая/точка с запятой приводятся к `;`;
- денежные суммы сохраняются целыми рублями;
- автоматическое формирование таблицы финансирования;
- автоматическая проверка целостности при запуске и после сохранения.

В исходных данных автоматически обнаруживаются проблемы, которые нельзя исправлять без решения пользователя: одна НИР без `CODVUZ` и три записи с `CODVUZ=31`, отсутствующим в справочнике `VUZ`.

## Запуск в Windows PowerShell

```powershell
cd "ПУТЬ_К_ПАПКЕ\LR1_Variant9_GUI"
python -m pip install -r requirements.txt
python main.py
```

Либо запустить `start.bat`.

## Файлы

- `main.py` — GUI;
- `database.py` — создание SQLite, очистка исходных данных, пересчет финансирования и проверка целостности;
- `data/lab1_v9.db` — готовая SQLite-база;
- `data/*.xlsx` — исходные таблицы варианта 9;
- `requirements.txt` — зависимости.

## Важно по ЛР №1

Пункты меню аналитики уже предусмотрены как часть общей оболочки, но детальные отчеты по вузам/ГРНТИ/характеру НИР относятся к последующим лабораторным работам. Это соответствует методичке, где для ЛР №1 требуется разработка функциональных спецификаций, а реализация информационной структуры и обработки выполняется далее.


## Исправление `database is locked`
В исправленной версии SQLite работает в режиме WAL, а соединения ждут освобождения базы до 30 секунд.
Не запускайте две копии программы одновременно и не держите `lab1_v9.db` открытой на запись в DB Browser for SQLite.
