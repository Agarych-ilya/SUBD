## Правки после обсуждения замечаний преподавателя

- ID скрыт в таблице НИР, но остаётся внутренним идентификатором базы;
- последние три столбца НИР расположены в порядке: «Плановое финансирование» → «Должность руководителя» → «Наименование НИР»;
- ширины столбцов НИР подбираются по данным и компактным заголовкам; длинные значения переносятся, высота строк подстраивается, наименование занимает оставшееся пространство;
- в справочнике вузов слева показаны код, краткое название, город, субъект РФ, округ и статус; длинные наименование и юридическое наименование перенесены в конец, ширины подбираются по содержимому, текст переносится по строкам;
- в финансировании и справочнике ГРНТИ все столбцы подогнаны под содержимое без растягивания последнего на всю ширину окна; длинные названия рубрик переносятся;
- заголовок номера сокращён до «Рег. номер», столбец имеет компактную ширину;
- по умолчанию НИР сортируются по коду вуза, затем рег. номеру;
- кнопка «Сортировка по ключу» снизу сортирует по возрастанию кода вуза, затем рег. номера; обычная сортировка по отдельному столбцу доступна через его заголовок;
- рег. номера сортируются как текст и сохраняют ведущие нули: `07` и `7` различаются;
- снизу таблицы НИР доступны «Добавить», «Изменить», «Удалить», «Фильтр», «Сортировка по ключу»;
- география и ГРНТИ настраиваются в окне «Фильтр»; «Применить» подтверждает условия, «Отмена» восстанавливает прежние значения и зависимые списки, «Сбросить» очищает фильтры для последующего применения;
- на основной странице показаны только состояние фильтра и число строк; выбранные условия видны в подсказке при наведении на состояние;
- текстовый поиск открывается отдельной кнопкой «Поиск», работает без учёта регистра кириллицы и с буквальным поиском символов `%` и `_`; поиск выполняется внутри выбранных фильтров, очистка поиска и сброс фильтров независимы;
- добавление и изменение выполняются в отдельной форме; изменение также открывается двойным щелчком;
- вуз выбирается из справочника, его краткое название подставляется автоматически;
- регистрационный номер вводится вручную при добавлении и изменении; допускает буквы, префиксы и ведущие нули, при смене вуза не перезаписывается;
- при совпадении введённого номера с номером другой НИР того же вуза сохранение отклоняется; программа не назначает другой номер самостоятельно;
- характер НИР первоначально показывает «Выберите характер…» и требует явного выбора;
- имя руководителя обязательно, но его формат свободный; «Фамилия И.О.» остаётся только подсказкой; должность руководителя обязательна;
- первый код ГРНТИ вводится по маске `XX.XX.XX`, второй код необязателен;
- плановое финансирование вводится целыми неотрицательными рублями;
- после сохранения выделяется сохранённая НИР; если она скрыта фильтром, фильтр сбрасывается с уведомлением;
- удаление требует подтверждения с номером и названием НИР;
- суммы и количество НИР по вузу пересчитываются в той же транзакции, что и изменение НИР;
- под таблицей финансирования показана сумма столбца «Количество НИР»; при фильтрации итог рассчитывается по отображаемым строкам и обновляется после пересчёта;
- работы без кода вуза или с кодом, отсутствующим в справочнике, включены общей строкой «Вуз не определён»: показываются их суммарный план и количество; код и факт показаны прочерками, строка доступна только на просмотр;
- географические списки образуют цепочку «Округ → субъект РФ → город → вуз»; нижние списки учитывают верхние значения, выбор разрешён с любого уровня, недопустимые зависимые значения сбрасываются;
- фильтр ГРНТИ использует рубрики справочника и первые две цифры любого из двух кодов; приоритета первого кода нет; география и ГРНТИ работают совместно независимо от порядка выбора;
- в меню «Данные» выбираются НИР, финансирование вузов, справочник вузов и ГРНТИ; служебные действия, редактирование и журнал доступны в меню «Опции»;
- журнал хранит время, действие и значения до/после изменения, включая фактическое финансирование;
- перед первой миграцией сохраняется однократная резервная копия `data/backups/lab1_v9_before_changes.db` через SQLite backup, включая данные WAL; повторный запуск её не заменяет;
- пара «код вуза + рег. номер» защищена составным уникальным индексом SQLite; дополнительный индекс запрещает повторы номеров среди записей с неизвестным вузом;
- при первой миграции повторяющиеся номера заменяются по правилу `max + 1` внутри вуза и того же префикса, с сохранением ведущих нулей; первая запись пары по ID сохраняет номер, остальные получают новые номера, все замены записываются в журнал;
- перед перенумерацией сохраняется отдельная копия `data/backups/lab1_v9_before_unique_nir_key.db`; отметка о миграции предотвращает повторное изменение номеров.

### Принятые правила и открытые вопросы

Проверка уникальности выполняется внутри вуза. В исходных данных было 13 повторов пары. Они исправлены без удаления работ: например, номер `018` в вузе №1 заменён у второй записи на `035`, поскольку максимум был `034`. Для форматов с префиксом увеличивается числовая часть: `d-08` → `d-17`, `1.01` → `1.20`. Номера `07` и `7` по-прежнему различаются. Внутренний ID остаётся первичным ключом для ссылок и журнала, а пара `(codvuz, rnw)` является составным уникальным ключом.

При открытии старой НИР распознаются оба кода ГРНТИ, даже если они были разделены пробелом или имели лишнюю завершающую точку. Форма сообщает о нормализации; изменения попадают в базу и журнал только при сохранении.

Пересчёт перенесён в «Опции», четыре уровня географического фильтра реализованы. Все четыре таблицы доступны по вкладкам сверху, под меню внутри окна; переключение через «Данные» также сохранено. Отдельное название таблицы справа убрано: активная таблица обозначена выбранной вкладкой. Названия вкладок не сокращаются; в узком окне доступны кнопки прокрутки. Справочники вузов и рубрик остаются доступны только на просмотр.

### Проверка

```bash
python -m unittest -v test_nir
```

Тесты используют временные базы. Проверяются ручной ввод номеров и ведущие нули, конфликт двух форм без перенумерации, свободный формат имени и обязательная должность, добавление/изменение/удаление, пересчёт, история, откат при ошибках, защита от устаревшей формы, каскадные фильтры и отмена их настроек, независимый поиск по кириллице, меню внутри окна, сортировка и выделение новой строки. Отдельно проверяется восстановление связей с вузами: резервная копия, причина в журнале и откат всего исправления при конфликте ключа.

Четыре исходные ошибки связи с вузами исправлены 22.10.2026 как учебные назначения, разрешённые преподавателем: НИР ID=1 (`031`) → вуз 1; ID=106,107,108 (`201`, `202`, `204`) с кодом 31 → вуз 33. Историческая принадлежность этих НИР не подтверждена. Перед исправлением сохранена копия `data/backups/lab1_v9_before_vuz_repair.db`, в журнале записаны исходные значения и причина учебного исправления. Все 400 НИР и сумма 360 917 220 руб. сохранены. Проверка рабочей базы не находит ошибок или предупреждений.

## Аналитические отчёты — этап 2

Меню «Анализ» открывает отдельные немодальные окна. Повторный выбор того же отчёта активирует уже открытое окно и обновляет данные, сохраняя его фильтр.

- **По вузам:** № п/п, вуз, количество НИР, сумма планового финансирования, фактическое финансирование. План и количество рассчитываются по НИР, факт берётся из таблицы финансирования один раз на вуз. Внизу закреплена строка «Итого» по всем трём числовым показателям. Вузы без работ в выборке не выводятся.
- **По рубрикам ГРНТИ:** двузначный код рубрики, название и количество НИР. Работа учитывается по обоим кодам, но только один раз внутри одной рубрики. Показаны рубрики с найденными работами. Общего итога по строкам и денежного столбца нет: финансовая часть ГРНТИ оставлена до отдельного уточнения. Под таблицей указано число уникальных НИР исходной выборки, а не сумма попаданий по рубрикам.
- **По характеру:** три строки — фундаментальные, прикладные, разработки; № п/п, характер, количество НИР и сумма планового финансирования последним столбцом. Пустые группы показаны с нулями. Внизу закреплено «Итого» по количеству и плану.

У каждого отчёта свой фильтр «Округ → субъект РФ → город → вуз». Выбор возможен с любого уровня. «Применить» пересчитывает отчёт; «Отмена» не изменяет действующий отбор; «Сбросить» очищает черновик условий для последующего применения. Основная таблица НИР и остальные отчёты сохраняют собственные настройки.

«Обновить» перечитывает текущие данные базы. Открытые отчёты также обновляются после сохранения НИР и финансирования из главного окна. При открытии или обновлении отчёта введённые несохранённые фактические суммы сохраняются тем же механизмом, который используется перед редактированием НИР. Введённый факт не заменяется нулями.

Отчёты доступны только на просмотр. Числовые столбцы сортируются как числа, денежные суммы отображаются с пробелами между разрядами. Закреплённая строка итогов не участвует в сортировке и остаётся видимой при прокрутке.

Без фильтра на текущей базе: **400 НИР, план 360 917 220 руб., факт 0 руб.** Итоги по количеству и плану совпадают в отчётах по вузам и характеру. НИР без действующего вуза, если такие появятся, сохраняются в общей выборке и показаны группой «Вуз не определён» с неизвестным фактом.

Команда проверки прежняя: `python -m unittest -v test_nir`. В наборе 33 теста, включая подсчёт обоих кодов ГРНТИ без удвоения одной рубрики, правильный факт без умножения на число НИР, пустые выборки, фильтры, обновление окон и отсутствие изменений базы при расчёте.


## Исправление `database is locked`
В исправленной версии SQLite работает в режиме WAL, а соединения ждут освобождения базы до 30 секунд.
Не запускайте две копии программы одновременно и не держите `lab1_v9.db` открытой на запись в DB Browser for SQLite.
